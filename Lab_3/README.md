# Лабораторна робота №3: Кастомні анотації в Spring Boot

Цей модуль містить реалізацію трьох кастомних анотацій у Spring Boot застосунку, кожна з яких демонструє унікальний механізм розширення фреймворку (Bean Validation, Meta-annotation та MVC Argument Resolver).

---

## 🛠 Реалізовані анотації та механізми

### 1. Bean Validation Constraint (`@ValidTaskDates`)
* **Призначення:** Кастомне бізнес-правило перевірки коректності часових проміжків для DTO об'єкта `TaskDto`. Перевіряє, щоб дата завершення задачі (`dueDate`) не передувала даті її створення (`createdAt`).
* **Класи:**
    * `@ValidTaskDates` — анотація на рівні класу DTO.
    * `TaskDatesValidator` — валідатор, що реалізує інтерфейс `ConstraintValidator<ValidTaskDates, TaskDto>`.
* **Відповідність критеріям (AC 1–3):**
    * Автоматично підхоплюється Spring Validation без явного створення екземплярів вручну.
    * Пропускає валідацію, якщо `dueDate >= createdAt`.
    * Генерує чітке повідомлення про помилку валідації при порушенні правила.

---

### 2. Композитна анотація (Meta-Annotation) (`@PostJsonCreated`)
* **Призначення:** Об'єднує дві регулярно використовувані анотації в одну для зменшення дублювання коду на рівні контролерів.
* **Об'єднані анотації:**
    * `@PostMapping`
    * `@ResponseStatus(HttpStatus.CREATED)`
* **Відповідність критеріям (AC 4–5):**
    * Застосовується до методів контролера (`TaskController`).
    * Забезпечує створення ресурсів через HTTP POST та повернення статусу `201 Created` під час виконання запиту.

---

### 3. Кастомна анотація-резолвер аргументів MVC (`@CurrentUserId`)
* **Призначення:** Дозволяє методам контролера отримувати ID поточного користувача безпосередньо з контексту HTTP-запиту (наприклад, із заголовка `X-User-Id`), уникаючи дублювання логіки витягування заголовків.
* **Класи:**
    * `@CurrentUserId` — анотація параметрів методів контролера.
    * `CurrentUserIdArgumentResolver` — реалізація `HandlerMethodArgumentResolver`.
    * `WebConfig` — реєстрація резолвера у `WebMvcConfigurer`.
* **Відповідність критеріям (AC 6–8):**
    * `supportsParameter()` повертає `true` тільки для параметрів з анотацією `@CurrentUserId`.
    * `resolveArgument()` витягує та конвертує значення з HTTP-запиту в тип `Long`.
    * Витягнутий ID передається безпосередньо в тіло методу контролера.
